Todo lo que hace funcionar al servidor

Una implementación compacta, explícita y sin dependencias externas: desde el socket TCP hasta la respuesta HTTP completa.

Sockets TCP puros

Creación del socket, bind, listen y accept directamente sobre la API de Linux.

Parsing HTTP/1.1

Archivos estáticos

Servicio desde www/, resolución de / a index.html y envío por bloques con Content-Length y Last-Modified.

www streaming 200 / 404

Tipos MIME

Detección por extensión para HTML, CSS, JavaScript, imágenes, JSON, PDF y más. Cualquier extensión desconocida cae en application/octet-stream.

mime.c 13 tipos charset

Concurrencia con epoll

Sockets no bloqueantes, un bucle de eventos y una máquina de estados por conexión. Hasta 512 clientes atendidos sin bloquear al servidor.

epoll O_NONBLOCK 512 clientes

Seguridad primero

Validación de rutas, rechazo de .., canonicalización con realpath(), límites de solicitud y compilación endurecida.

realpath límites FORTIFY

Roadmap

Construido fase por fase

El proyecto avanza desde un eco TCP hasta un servidor concurrente con respuestas HTTP completas y protecciones reales.

  1. 01

    Servidor TCP completada

    Socket, bind, listen, accept y eco de datos.

  2. 02

    Primera solicitud HTTP completada

    Parsing de GET, URI, versión y encabezados básicos. Respuestas 200, 400 y 405.

  3. 03

    Archivos estáticos completada

    Servicio desde www, index.html para / y control de 403, 404 y 500.

  4. 04

    Respuestas completas completada

    MIME, Server, Date, Content-Type, Content-Length y Last-Modified.

  5. 05

    Seguridad completada

    Límites estrictos, bloqueo de traversal, enlaces simbólicos seguros y binario endurecido.

  6. 06

    Concurrencia con epoll completada

    Sockets no bloqueantes, bucle de eventos, escritura por bloques y 512 conexiones simultáneas.

  7. 07

    Conexiones persistentes pendiente

    Reutilización de conexiones HTTP/1.1 y keep-alive para varias solicitudes por cliente.

La protección contra directory traversal también está activa. Una ruta que intente salir de www se rechaza con 403 Forbidden:

curl -i --path-as-is http://127.0.0.1:8080/../../etc/passwd

Puesta en marcha

Compilar y ejecutar

Solo necesitas Linux, gcc y make. Ejecuta el servidor desde el directorio minihttpd/ porque www se resuelve relativo al directorio de trabajo.

terminal — compilar y arrancar 
$ cd minihttpd
$ make
# compilación limpia con -Wall -Wextra -Wpedantic
$ ./minihttpd 8080
MiniHTTPd escuchando en el puerto 8080
# epoll, max 512 conexiones
terminal — probar la respuesta 
$ curl -i http://127.0.0.1:8080/
HTTP/1.1 200 OK
Server: MiniHTTPd/1.0
Content-Type: text/html; charset=utf-8
Connection: close

$ curl -sS http://127.0.0.1:8080/image.jpg -o /tmp/image.jpg
$ sha256sum www/image.jpg /tmp/image.jpg
# los hashes deben coincidir
